## 오른쪽 버튼·스크롤과 아이콘 도구 모음 이후

- 하단 바의 글자·숫자·장식 별을 제거하고 오브제 보관함, 코드, 실행 취소·다시 실행, 자석 스냅, 격자를 같은 선 굵기의 SVG 아이콘 여섯 개로 구성했다. 바 배경은 헤더와 동일한 검정이며 활성 색은 헤더 버튼과 동일한 연노랑이다. 접근성 이름과 툴팁을 유지했다.
- GPU 검사: 일반 포인터 이동의 시점 고정, 회전 도구에서도 왼쪽 버튼의 이동 전용 동작, 오른쪽 드래그 회전과 위치 보존, 오른쪽 손잡이, 터치 손잡이, 제한된 배경 시점 이동·확대, 드래그 취소를 확인했다.
- 깊이 스크롤은 한 입력 묶음당 한 번 반영하며 0–0.65 범위를 지킨다. Escape 취소 후 지연된 변경이 남지 않는다. 미적용 코드에서는 오른쪽 드래그와 깊이 편집을 막는다.
- Chromium 1440×950: 실제 오른쪽 드래그 회전·손잡이, 왼쪽 이동, 방향키 크기 조절, 연속 휠 깊이 변경과 한 번 실행 취소, 배경 오른쪽 드래그·휠 확대, 일반 포인터 이동 시 시점 고정 통과. 보관함 위 휠은 목록만 스크롤한다.
- 스냅·격자 아이콘 활성 상태와 헤더 색 일치, 코드 아이콘 열기, 감상 중 오른쪽 클릭이 콘텐츠를 열지 않는 것, 깊이 스크롤 중 Escape 취소 확인. 테스트로 추가한 오브제는 실행 취소하여 복원했다.
- 390×844, 320×700에서 모든 아이콘이 화면 안에 표시되며 가로 넘침 없음. 화면 기록은 `output/playwright/dock-inputs-selected.png`, `dock-icons-mobile-390.png`, `dock-icons-mobile-320.png`.
- 자동 검사 49/49 통과. POM 변화 14,108픽셀과 32개 디자인 렌더링 검사 통과, GPU·브라우저 오류 0.

## 감상·편집 동작 분리와 자연스러운 창 크기 조절 이후

- 감상 모드의 포인터 패럴랙스를 복원했다. 편집 모드의 오른쪽 드래그·깊이 스크롤은 유지한다. GPU 검사에서 감상 포인터 반응, 편집 시점 고정, 감상 중 편집용 휠·오른쪽 버튼 미사용, 움직임 줄이기 분기를 확인했다. GPU 오류 0.
- 오브제·코드 창은 중립적인 검정, 얇은 테두리, 둥근 모서리와 부드러운 그림자로 변경했다. 헤더 제어 아이콘을 통일하고 중복 파일명과 반복 선 장식을 제거했다.
- 보관함·코드·속성 모두 네 가장자리와 네 모서리에서 크기를 조절한다. 반대편 가장자리 고정, 최소 크기·화면 경계, 최대화·복원, Escape 취소와 키보드 조절을 확인했다.
- 자동 검사 53/53: 반대쪽 기준점 보존, 네 모서리, 최소 크기·화면 제한, 제한 지점에서 포인터를 되돌릴 때의 좌표 복원을 추가 검증했다.
- Chromium 1440×950: 보관함의 오른쪽·왼쪽·위쪽 크기 변경과 3열 재배치, 최대화 시 5열 표시, 코드의 두 모서리 크기 조절, 더블 클릭 최대화·복원, 파일 목록 접기, 속성 창 크기 변경 통과. 새로고침 뒤 데스크톱 크기와 위치 복원 확인.
- 390×844 / 320×700: 코드와 보관함 상단 드래그로 높이 변경, 하단 위치 고정, 새로고침 후 높이 유지, Escape 취소, 마지막 위젯 스크롤 접근과 가로 넘침 없음 확인. 그림 비율을 미리 지정해 초기 로딩 시 스크롤 위치가 흔들리지 않게 했다.
- 화면 기록: `output/playwright/windows-redesign-final.png`, `library-expanded.png`, `windows-code-mobile-390.png`, `library-mobile-settled.png`. 테스트는 localhost 별도 저장 공간에서 진행했고 방 문서와 콘텐츠를 초기화하지 않았다.
