# ROOM — An unfinished exhibition

이미지, 소리, 문장을 겹쳐 놓는 개인 전시 공간. 꾸미기에서는 코발트 배경과 큰 활자 위에 위젯을 놓고 모양을 바꾼다. 감상에서는 같은 홈 구성 위에서 최대 세 명의 작은 사람이 굴에서 불규칙하게 나와 위젯을 방문하고 돌아간다. 오브제는 평면 이미지이며 **Parallax Occlusion Mapping(POM)** 으로 이미지 내부의 깊이를 표현한다.

## 실행

Node.js 20.19+ 또는 22.12+가 필요하다.

```sh
npm install
npm run dev
npm test
npm run build
npm run preview
```

| 주소 | 화면 |
| --- | --- |
| `/` | `master.room` 감상. 큰 글자와 위젯의 가장자리를 걸어 다니는 작은 사람. |
| `/?edit=1` | 하단 오브제 카탈로그, 선택 오브제 코드와 전체 방 코드. |
| `/compositions.html` | 전체 / 근접 / 넓게 보기 비교. |
| `/legacy.html` | 기존 SVG ROOM. |

상·하단의 검은 띠에는 ROOM 브랜드, 현재 방, 편집 전환과 전시 문구를 표시한다. 장면의 흰색 제목은 방 파일의 `title`과 함께 바뀌며 현지 시각도 표시한다. 하단의 ROOM — VOL. 001 / 2026 바를 위로 끌면 오브제 서랍이 올라온다. 바는 서랍의 위쪽 끝으로 함께 이동하고 아래로 당기면 감상으로 돌아간다. 클릭과 키보드 위·아래 방향키도 지원한다. 서랍이 올라오는 만큼 작품 영역의 높이가 줄어든다. 코드는 오른쪽에서 열리며 작품 영역의 폭도 그만큼 줄어든다. 창 제목 옆 도킹 아이콘으로 창을 분리하거나 다시 붙일 수 있고, 제목을 끌어 아래·오른쪽 가장자리에 놓아도 도킹한다. 붙어 있는 창의 경계를 끌면 작품과 도구의 비율을 바꿀 수 있다. 도구 창 배치와 크기는 방 내용과 별도로 저장한다. 검은 코드 창의 왼쪽에는 번호가 붙은 방 파일 목록, 오른쪽에는 큰 파일명과 얇은 밑줄 탭, 흑백 문법 강조를 사용한다. 왼쪽 위 버튼으로 파일 목록을 접으면 코드가 창 전체를 채운다. 창이나 탭을 닫아도 방 파일과 초안은 보존된다. 가져오기·내보내기는 왼쪽 방 파일의 `···` 메뉴에 있다.

## 작품 구성

1. **하단 바를 위로 끌어올린다.** 오브제 서랍에서 14종의 위젯을 가로로 스크롤하며 고른다. 작은 순번과 큰 종류명, 실제 색의 위젯 미리보기를 얇은 구분선에 맞춰 표시한다.
2. 위젯 종류를 누르면 여러 디자인이 펼쳐진다. 원하는 모양을 눌러 추가하거나 화면에 끌어 놓는다. 전체 목록에서도 대표 디자인을 바로 끌어 놓을 수 있다.
3. 왼쪽 드래그는 선택·이동에 사용한다. 오른쪽 드래그는 **회전**, 크기 도구를 선택한 뒤 오른쪽 드래그는 **크기**를 바꾼다. 선택한 오브제 위에서 스크롤하면 **이미지 속 깊이**를 조절한다. 회전·크기 손잡이도 오른쪽 버튼으로 드래그하며, 터치와 방향키 조작은 유지한다.
4. 선택 옆의 `◈`로 배치와 콘텐츠를 유지한 채 디자인을 바꾼다. 흑백 이름 라벨이나 `</>`를 누르면 해당 오브제의 코드가 열린다. 큰 종류명 아래에 ID를 표시하고 위치·회전·크기·표시 내용을 JSON으로 펼쳐 읽는다. 복제와 삭제도 여기에 있다.
5. 코드를 수정하고 **적용** 또는 `⌘ Enter`를 누른다. Windows/Linux는 `Ctrl`을 사용한다.
6. 꾸미기에서 위젯을 가볍게 누르면 해당 오브제의 코드가 열린다. `appearance` 안의 `date`, `time`, `text`, `value`로 표시 내용을 바꾼다. **전체 코드 ↗**는 방 전체로 전환한다. 오브제 간 전환에도 초안은 유지되고, 적용한 수정은 저장과 실행 취소를 공유한다. 잘못된 코드는 초안으로 남기고 마지막 정상 장면을 유지한다.
7. **서랍 위쪽 바를 아래로 당기면** 기존 홈의 큰 ROOM 활자 위에서 작은 사람이 움직인다. 오브제를 누르면 그쪽을 가까이 본다.

감상은 기존의 전체 화면 콜라주·큰 ROOM 활자·제목·인쇄 조각을 유지한다. 별도의 상자, 감상용 제목, 주민 선택 패널은 없다. 정제된 검은 아치 모양의 굴에서 캐릭터가 한 명씩 불규칙하게 나온다. 한 번에 한 명일 수도 있고 최대 세 명까지 밖에 머무른다. 목적지를 정한 뒤 실제로 그려진 글자와 위젯의 위쪽 외곽을 따라 이동하고, 활동을 마치면 굴로 돌아가 사라진다. 방문 사이에는 아무도 없는 조용한 간격도 있다. 모자, 스카프, 옷깃의 작은 색으로 구분한다. 걷기 → 도약 준비 → 중력에 따른 비행 → 접촉 착지 → 잠깐 쉬기가 이어진다. 출발 전에 왕복 가능한 경로를 찾고, 같은 위젯을 동시에 방문하지 않도록 배정한다. 기본 전체 콜라주는 최대 축소 구도이며, 편집 영역의 크기가 변해도 현재 확대 비율을 유지한다.

캐릭터·발·그림자는 위젯과 같은 방 좌표 및 카메라를 사용한다. 걸음의 지지 구간에서는 발의 위치를 고정하고, 곡선이나 기울어진 테두리에서는 발마다 접촉 높이를 따로 찾는다. 비행 중에는 앞쪽 위젯에 가려질 수 있으며 착지는 목적지 도착 시간이 아니라 표면을 아래로 통과하는 순간에 결정한다. 이는 X/Z 평면에 중력을 두고 Y를 앞뒤 레이어로 쓰는 2.5D 종이 세계다. 부유하거나 살짝 회전하는 위젯의 접점도 함께 이동한다.

꾸미기에서는 캐릭터를 숨기고 물리 시간을 멈춘다. 기존 좌측 하단의 일시 정지가 캐릭터와 장면을 함께 멈춘다. 이전 방의 미디어 연결 데이터와 표시 설정은 유지하며, 감상 클릭은 확대 관찰에 사용한다. 다른 방은 꾸미기의 방 파일 목록에서 연다. SUN에서는 창 안으로 내려가 해변의 선베드에 눕고, 날짜에서는 종이 가장자리를 붙잡고 한 장 전체가 크게 펄럭이는 모습을 보여 준다. 음악에서는 회전하는 레코드 위에서 춤추고, 메모에서는 문장 아래에 앉아 책을 읽는다. 방문이 끝나면 테두리로 돌아와 다시 이동한다. 한 위젯에는 한 명만 머물며 이 장면은 저장한 날짜나 배치를 바꾸지 않는다. [상호작용 설계](docs/NPC-REDESIGN.md)에 좌표와 접촉 기준을 정리했다.

표시 설정은 오브제의 선택적 `appearance`에 저장한다. 기존 방 파일은 그대로 읽힌다. 예: `"appearance":{"date":"2026-08-18","time":"10:08","text":"MY LITTLE ROOM","value":"128.00"}`. 날짜와 시간의 고정값이 없으면 원래처럼 현재 날짜와 시간을 표시한다. 기본 홈 구성은 종전의 다섯 오브제로 복원했으며 이미 저장된 배치는 덮어쓰지 않는다.

시점은 작품을 정면에서 보는 작은 범위로 제한한다. 감상 모드에서는 마우스 움직임에 따라 시점이 조금 기울며 이미지 내부의 깊이가 드러난다. 편집 모드에서는 시점을 고정하고, 빈 배경의 오른쪽 드래그와 스크롤로 시점·확대를 직접 조절한다. 확대·축소와 저장된 구도에도 같은 제한을 적용한다. **평면으로 보기**는 POM 깊이를 0으로 바꾸고 격자를 표시한다. **기본 구도**로 돌아오면 깊이가 복원된다.

오브제 추가 때문에 시점이 자동으로 뒤로 물러나지 않는다. 화면 밖 조각은 **오브제 목록 → 시선 이동**으로 다시 찾는다. 오브제를 조작하는 동안에는 시점을 고정한다.

하단 도구 모음과 선택 정보, 코드 창은 흑백으로 통일한다. 이름과 단축키는 툴팁과 접근성 이름으로 제공한다.

연속 스크롤은 하나의 깊이 변경으로 저장해 한 번에 실행 취소한다. Escape로 취소하면 원래 깊이로 돌아가며, 미적용 코드가 있을 때는 회전·깊이 편집을 막는다. 보관함이나 코드 창 위에서는 기존 스크롤을 유지한다.

보관함과 코드 창은 검은 면, 흰 활자, 얇은 경계선으로 구성한다. 선택 라벨은 큰 종류명과 작은 ID·회전·배율을 조합한다. 속성 폼은 없다. 도킹된 창은 작품의 공간을 확보하며, 분리한 창은 제목 표시줄로 옮기고 가장자리로 크기를 바꾼다. 도킹 아이콘이나 제목 표시줄 더블 클릭으로 분리·재도킹하고, 창을 하단 또는 오른쪽 가장자리에 끌어도 다시 붙는다. 분리한 창의 최대화 아이콘으로 크게 펼칠 수 있다. **도구 창 정리**는 기본 배치를 복원한다. 도구 배치와 방 파일 목록의 접힘 상태는 방 문서와 별도로 저장한다.

| 단축키 | 동작 |
| --- | --- |
| G / T | 평면 이동 |
| R / S | 오른쪽 드래그의 회전 / 크기 도구 |
| 1 / 2 | 오브제 / 코드·방 파일 통합 창 열고 닫기 |
| 3 | 코드 창의 왼쪽 방 파일 목록 접고 펼치기 |
| 손잡이에 초점을 둔 뒤 방향키 | 회전·크기 미세 조절 |
| 창 제목·크기 손잡이에 초점을 둔 뒤 방향키 | 도구 창 이동·크기 조절 |
| F / H | 선택 조각 보기 / 기본 구도 |
| ⌘ Enter | 코드 실행 |
| ⌘ Z / ⌘ ⇧ Z | 실행 취소 / 다시 실행 |
| ⌘ S / ⌘ D | 저장 / 선택 조각 복제 |
| Delete / Escape | 선택 조각 삭제 / 진행 중 드래그 취소, 열린 창 또는 선택 닫기 |

## 위젯 모음

이미지 창, 음악 플레이어, 시계, 달력, 날씨 위젯, 메모, 카세트, 계산기, 터미널, 라디오, 다른 방, 픽셀 스케치, 영상 플레이어, 오실로스코프를 제공한다.

14종에 총 32개 디자인이 있다. 원판·캡슐·아치·구름·찢어진 종이·티켓·팔레트처럼 실루엣과 비율이 달라지며 클래식 창도 고를 수 있다. 날짜 위젯은 원형 날짜판·날짜 티켓·페이퍼 날짜·월간 달력 네 가지다. 투명한 모서리와 구멍은 뒤쪽 오브제의 클릭을 가로막지 않는다.

시계와 달력은 기기의 현지 시각·날짜를 사용한다. 배치한 시계는 분마다 갱신하며, 열면 초 단위 시각을 표시한다. 달력은 앞뒤 달 이동과 날짜 선택을 지원한다. 계산기는 키보드로도 사용할 수 있다. 픽셀 스케치는 16×16 그림을 그려 방 파일에 저장하며, 저장한 그림이 작품에도 반영된다. 카세트·라디오·오실로스코프는 기존 음악 모음과 개인 음원을 재생한다. 라디오의 주파수와 오실로스코프의 파형은 그래픽 표현이며 실제 방송 수신·신호 측정 기능은 아니다.

## `.room`과 화면 동기화

한 파일이 한 공간이다. 파일명과 내부 `room` ID를 분리하므로 파일명을 바꾸어도 연결이 유지된다. `master.room`은 시작 공간이다.

```text
room "my-room"
title "An unfinished\nexhibition."
composition "floor"
palette "citrus"
surface {"width":50,"depth":24,"wall":true}
light {"color":"#fff0ce","intensity":3,"cycle":"still"}
shader {"pattern":"grain","strength":0.12,"speed":0.35,"code":""}

// at [가로, 레이어 높이, 세로] · rotate [기울기, 평면 각도, 기울기]
object "camera-1" camera {"at":[-3,0.5,-1],"rotate":[0,-5,0],"scale":1.5,"relief":0.32,"color":"#edff52","action":"gallery","content":"photos"}
object "portal-1" portal {"at":[5,0.8,-4],"relief":0.4,"action":"room","content":"music"}
```

| 필드 | 의미 |
| --- | --- |
| `camera / turntable / lamp / book / portal / projector` | 이미지 창 / 음악 플레이어 / 날씨 위젯 / 메모 / 다른 방 / 영상 플레이어. 종류 ID와 콘텐츠 연결은 유지한다. |
| `clock / calendar / calculator / terminal / cassette / radio / sketch / scope` | 시계 / 달력 / 계산기 / 터미널 / 카세트 / 라디오 / 픽셀 스케치 / 오실로스코프. |
| `variant` | 위젯 디자인. 달력은 `orbit / ticket / peel / classic`. 생략한 기존 파일은 `classic`을 사용한다. 전체 조합은 `widget-catalog.js`에 있다. |
| `relief` | 이미지 내부 깊이, 0–0.65. 없는 예전 파일은 0.24를 사용한다. |
| `at` | 가로 위치, 레이어 높이, 세로 위치. |
| `rotate` | 가운데 값이 평면 회전. 다른 축의 기울기는 렌더링에서 ±12도로 제한한다. |
| `material` | `clay` 원본, `chrome` 크롬 프린트, `glass` 반투명, `ink` 흑백. |
| `surface` | `floor` 앞 레이어, `wall` 뒤 레이어. 기존 `surface` 방 설정은 파일 호환성을 위해 유지한다. |
| `motion` | `none / float / spin / pulse`. 회전도 작은 진폭의 평면 움직임으로 제한한다. |
| `composition` | `floor` 전체, `close` 근접, `graphic` 넓게. 세 구도 모두 같은 정면 방향을 유지한다. |
| `palette` | `citrus` 코발트, `berry` 주홍, `blue` 밤, `paper` 청록, `auto` 시간에 따른 전환. |
| `action` | `gallery / music / video / article / light / room / clock / calendar / calculator / sketch / none`. |

`shader.code`는 배경의 GLSL 함수 본문이다. `color`, `p`, `time`을 사용할 수 있다. 예: `return color * (0.8 + 0.2 * sin(p.x + time));`.

JSON 값만 파싱하며 JavaScript는 실행하지 않는다. 오류가 나면 마지막 정상 장면을 유지한다. 화면 편집은 해당 오브제 줄의 JSON 값만 바꾸며 다른 줄·들여쓰기·주석을 보존한다. 드래그 한 번과 코드 실행 한 번은 각각 실행 취소 한 번이다. 미적용 초안은 별도로 보관하고 화면 편집을 잠근다.

## 이미지 안의 깊이

`models.js`는 동일한 좌표로 컬러 그래픽과 높이 지도를 만든다. 각 작품은 네 꼭짓점의 평면 한 장이다. `relief.js`의 fragment shader가 접선 공간의 시선 방향으로 높이 지도를 32–64단계 탐색하고, 교차 전후를 보간해 텍스처 좌표를 결정한다. 큰 높이 차이는 부드럽게 연결하고 명시적인 텍스처 미분을 사용해 계단 현상을 줄인다.

구현 원리는 Tatarchuk의 [Practical Parallax Occlusion Mapping](https://advances.realtimerendering.com/s2006/Tatarchuk-POM.pdf)을 참고했다. 주변의 작은 인쇄 조각은 별도의 평면 인스턴스이며, POM은 각 창의 내부 표현에 사용한다. 프레임 외부는 투명하며 그림자도 외곽을 따른다. 클릭 판정은 높이 탐색과 알파 값을 함께 확인하므로 투명한 여백 뒤의 오브제를 선택할 수 있다. 임의의 사진을 자동으로 분석해 깊이 지도를 추출하는 기능은 포함하지 않는다.

## 저장과 미디어

방 코드·초안은 localStorage, 사진·오디오·영상은 IndexedDB에 저장한다. 서버 업로드는 하지 않는다. 기존 저장 데이터는 덮어 초기화하지 않으며 새 렌더러로 읽는다.

- `.room`: 현재 방의 마지막 정상 코드.
- `.roompack`: 모든 방의 정상 코드·초안·연결 미디어.
- 프로젝트 가져오기 전에 현재 방 코드의 복구 파일을 내려받는다.

기존 미디어 모듈과 연결 자료는 이전 전시 구현으로 보존한다. 현재 감상 화면은 관찰에 집중하며, 픽셀 스케치 편집을 제외한 미디어 창은 열지 않는다. 이전 이미지 창에는 새 디자인의 세 구도 스터디가 들어 있다. 개인 사진과 캡션을 연결할 수 있다. 글 세 편과 LP 여섯 장의 기존 제목·분위기 데이터를 유지한다. LP의 음원은 15–27초의 **직접 합성한 오리지널 사운드 스케치**이며 원본 아티스트 녹음이 아니다. 개인 음악으로 바꿀 수 있다. 영상 플레이어는 기본 모션 스터디와 기기 영상 파일을 지원한다.

미디어 창은 다른 방으로 이동하거나 감상·꾸미기 모드를 전환할 때 닫고 재생을 멈춘다. 움직임 줄이기는 감상 모드의 포인터 반응과 시점 이동의 보간, 부유, 조각 움직임을 멈춘다. 오른쪽 드래그나 스크롤처럼 직접 요청한 조작은 계속 사용할 수 있다.

계정·서버 동기화·공동 편집은 포함하지 않는다. WebGL 2가 필요하며 미디어 재생은 브라우저의 코덱 지원에 따른다.

배경의 격자와 물결 띠는 최대 줌아웃의 카메라 범위에 여유분을 더해 그린다. 가로가 넓거나 시점이 기울어도 화면 중간에서 인쇄가 끊기지 않는다. 네 열의 머리말과 오른쪽 활자는 공통 기준선에 맞춘다. 브라우저에서 직접 배치한 8개 오브제의 저장본은 [studio-layout.room](docs/studio-layout.room)에 있다.

14종의 기본 위젯은 큰 활자·넓은 색면·얇은 인쇄선으로 구성한 프린트 에디션이다. Visuelle에 소개된 [Tone](https://visuelle.co.uk/tone/)의 활자 위계와 [Ligne](https://visuelle.co.uk/ligne/)의 편집 그리드를 참고해 원본 그래픽으로 그렸다. 캐릭터는 실제 외곽선에 서고, 레코드의 밝은 라벨·해변의 빈 모래·메모의 독서 선을 사용한다. 기존 실루엣 디자인과 저장 파일의 디자인 ID는 유지한다.

`npm test`는 68개 검사를 실행한다. 화면 비율별 최대 축소·기울임에서 배경의 네 모서리 커버리지와 메모 독서 선의 접촉도 검사한다. 표시 날짜의 월말·윤년 처리, 저장·실행 취소, 서로 다른 높이의 도약, 5분간의 이동과 접촉 유지, 프레임 속도 독립성을 포함한다. GPU 검사는 실제 홈에서 추출한 발판 사이를 2분 동안 이동하며 접촉·모드 전환·일시 정지를 확인한다. `/tests/room-residents-browser.html`은 700초 동안 0~3명이 불규칙하게 출현하고 네 종류의 위젯을 방문한 뒤 굴로 돌아가는 과정, 종이와 손의 접촉, 동시 점유, 일시 정지, 모드 전환, 위젯 이동·회전·크기 변경·삭제와 방 전환을 검사한다. 장면 선택과 시간 슬라이더로 각 동작을 확대해 볼 수 있다. GPU 검사는 개발 서버의 `/tests/room-relief-browser.html`에서 POM의 픽셀 변화, 평면 형상, 카메라 제한, 움직임 줄이기, 드래그 취소, 회전·크기 손잡이, 조작 중 시점 고정, 32개 디자인의 투명 실루엣·구멍과 뒤쪽 오브제 클릭을 확인한다.

`/tests/room-layout-browser.html`에서 390·760·1200px 폭의 서랍·코드 창·작품 영역이 겹치지 않는지 확인한다. `/tests/room-object-code-browser.html`은 오브제 코드에서 전체 코드로 전환할 때의 초안 보존, 오브제별 입력 실행 취소, 공통 방 이력과 오류 복구를 검사한다.
